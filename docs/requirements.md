# 拾音 Shiyin：需求規格

> 第二版（只有自己用、依賴 Python）的規格用 `git show b621ed6:docs/archive/v2/requirements.md` 看。任務編號（T-…）的紀錄用 `git show b621ed6:docs/tasks.md` 看（Windows 版的 W#、T-W# 用 `git show 0419550^:docs/tasks.md`），選型實驗用 `git show b621ed6:docs/spikes/<檔名>` 看。
> 本文件定義「要做什麼」。怎麼做寫在 `design.md`，實作順序寫在 `tasks.md`。

## 2. 使用者與發布方式（2026-10-15 已確認）

- 使用者：公司同事和身邊的人，不一定是工程師，也不一定裝了開發工具。
- 發布方式：自己發布 DMG，不上 Mac App Store。原因是 app 要執行 claude、codex CLI，App Store 的沙盒不允許。
- 沒有 Apple Developer 帳號，所以不做公證。使用者第一次打開時要手動放行一次，安裝說明要教怎麼操作。
- 有些人沒有裝 claude 或 codex，要提供 Anthropic、OpenAI API key 的選項。

## 3. 範圍

### 3.0 必須做

- 錄音：麥克風，加上線上會議的系統聲音
- 即時逐字稿、錄音中做筆記
- 正式轉錄（Breeze ASR 25）、說話者辨識
- AI 會議紀錄：範本、待確認、手動編輯、每一條都能跳到錄音
- 匯入與匯出：錄音、逐字稿、會議紀錄、整場會議的封包
- 全文搜尋、倍速播放
- 首次使用引導、DMG 發布、從第二版遷移
- 資料夾、全域快捷鍵、app 內更新

### 之後再做（3.1 以後）

行事曆整合（自動帶入會議名稱和與會者）、iPhone 版、多人即時協作、雲端同步。

### 不做

上 Mac App Store、支援 Intel Mac 或 macOS 26 以前的版本、把錄音上傳到任何雲端（使用者自己連上的企業伺服器例外，見第 36 節）。

## 4. 資料與隱私原則

| 項目 | 原則 |
|---|---|
| 錄音檔 | 只存在本機，不會上傳。要匯出或分享都由使用者自己操作。例外：使用者登入企業伺服器、正式轉錄選了它時（R50），錄音送到公司自己的伺服器轉錄，轉完就刪 |
| 轉錄（即時、正式） | 在本機完成，不連網（正式轉錄選企業伺服器時例外，R50） |
| 整理成會議紀錄 | 把逐字稿文字、使用者的筆記、詞彙表、會議基本資料，送到使用者選的服務（Claude、Codex、Anthropic API、OpenAI API、Gemini API、OpenAI 相容 API、企業伺服器 R51）。選「不整理」就完全離線；OpenAI 相容 API 填本機的網址（Ollama、LM Studio）時，內容也不會離開電腦 |
| 對會議提問、猜說話者（3.5） | 跟整理一樣，把逐字稿、會議紀錄、問題送到使用者選的整理工具；跨會議提問只送找到的相關會議片段 |
| 聲紋（3.5） | 說話者的聲音特徵只存在本機的資料庫，不上傳、不放進匯出的封包；設定裡可以查看、刪除、關閉 |
| API key | 存在 macOS 鑰匙圈，不寫進檔案或 log |
| 使用數據 | 2026-10-22 起（R40）：發布版本有設定統計網址時，每天最多送一份**匿名的使用統計**（版本、系統、錄音和轉錄的分鐘數、用了哪些功能、失敗次數），**不含任何會議內容**；預設開啟，設定 → 進階可以關掉。沒有統計網址的版本、DEBUG 版都不送。「回報問題」只打開瀏覽器的 GitHub 頁面，使用者看過內容、自己按送出；不含會議內容 |
| 資料位置 | `~/Library/Application Support/Shiyin`，權限 700 |

## 5. 功能需求

驗收條件的格式是「當…，系統應…」。優先級：**P0** 是 3.0 一定要有；**P1** 是 3.0 盡量做到，來不及可以延到 3.1。

### R1 錄音（P0）

- R1.1 系統應可以錄麥克風，並讓使用者選擇輸入裝置。
- R1.2 系統應可以錄電腦播放的聲音，例如 Zoom、Google Meet、Teams、瀏覽器裡的線上會議。來源可以選「麥克風」「系統聲音」「兩者都錄」。
- R1.3 錄音中應可以暫停和繼續。
- R1.4 錄音中應顯示經過時間，以及每個來源各自的音量。
- R1.5 當 app 當掉或電腦突然關機時，最多只能遺失最後幾秒的錄音，下次開啟時要自動復原。
- R1.6 應可以連續錄音至少 4 小時。
- R1.7 關掉主視窗後錄音應繼續進行；從選單列可以看到錄音狀態，也可以暫停、停止。
- R1.8 第一次錄音時，應依序說明用途並請求麥克風和系統聲音權限。使用者拒絕的話，要說明到哪裡打開。
- R1.9 錄音中和轉錄中，系統不應進入閒置睡眠。

### R2 即時逐字稿與錄音中筆記（P0）

- R2.1 錄音中應即時顯示逐字稿：一講話就出現暫定文字，定稿延遲在 5 秒以內。
- R2.2 錄音中可以往回捲動看前面的內容；使用者正在往回看時，新文字進來也不要把畫面拉走。
- R2.3 錄音中可以自己打筆記，每一行都會記下當下的錄音時間。整理時 AI 會參考這些筆記。
- R2.4 錄音中可以按一個鍵標記「重點」。標記會顯示在時間軸上，整理時也會被當作重點。
- R2.5 即時逐字稿只是預覽。錄音結束後，改用正式轉錄的結果（R4）。

### R3 匯入（P0）

- R3.1 應可以匯入 macOS 讀得到的音訊和影片檔，至少包含 m4a、mp3、wav、aac、flac、caf、aiff、mp4、mov。匯入方式有四種：拖進視窗、⌘O、拖到 Dock 圖示、Finder 的「打開方式」。
- R3.2 會議日期預設從檔名推算（沿用第二版的規則），推算不出來就用檔案的修改日期。
- R3.3 應可以匯入整場會議的封包（.shiyin，見 R7.4），完整還原錄音、逐字稿、會議紀錄和筆記。
- R3.4 應可以匯入逐字稿檔（srt、vtt、txt），可以單獨匯入，也可以跟錄音一起。只有逐字稿時不用轉錄，直接整理。
- R3.5 應可以匯入 Markdown 檔，當成這場會議的使用者筆記。

### R4 正式轉錄（P0）

- R4.1 錄音結束或匯入後，系統應在本機用 Breeze ASR 25 轉錄，並把詞彙表帶進去當提示。設定裡可以改用 macOS 內建的語音辨識：不用下載模型、速度快很多，但不吃詞彙表（2026-10-15 依真人會議的實測加入，見 D11）。
- R4.2 轉錄中應顯示進度和預估剩餘時間，並且可以取消、重試；app 中途被關掉的話，下次開啟時自動重跑。
- R4.3 一次只轉錄一場，其他場排隊等待。
- R4.4 辨識信心低的段落要標示出來。
- R4.5 使用者不需要安裝 Python、Homebrew 或 ffmpeg。

### R5 說話者辨識（P0）

- R5.1 正式轉錄時，系統應分出不同的說話者，逐字稿每一段都標上「說話者 1」「說話者 2」等標籤。
- R5.2 使用者可以幫說話者改名。改名後，整場的逐字稿和會議紀錄都改用新名字。
- R5.3 整理時，AI 要知道每段話是誰說的；待辦的負責人優先使用說話者的名字。

### R6 會議紀錄（P0）

- R6.1 整理工具可以選 Claude（claude CLI）、Codex（codex CLI）、Anthropic API、OpenAI API，或「不整理」。選 API 的話，要填 API key，也可以選模型。3.4 加上 Gemini API、OpenAI 相容 API，見 R17。
- R6.2 應提供範本：一般會議、一對一、訪談、課堂／演講、腦力激盪。使用者也可以自己新增範本，自訂要哪些段落、每個段落怎麼寫。每場會議可以選範本，換了範本之後可以重新整理。
- R6.3 會議紀錄依範本包含以下內容：標題、摘要、決議、待辦（負責人、期限）、未決問題、依議題分段的詳細內容、自訂段落、待確認。
- R6.4 **每一條紀錄都要附上錄音時間點**，點一下就從錄音的那個位置開始播放（「秒聽紀錄」）。
- R6.5 待確認與校稿沿用第二版：回答題目後，AI 依答案修正紀錄；略過的題目直接移除。
- R6.6 使用者可以直接編輯會議紀錄，包括新增、刪除、修改條目。
- R6.7 每次修改都要留版本，並可以復原。修改包括 AI 整理、校稿、手動編輯、用詞修正。
- R6.8 整理規則沿用第二版：期限要換算成實際日期、負責人只填明確提到的人、推測出來的專有名詞要列進待確認。

### R7 匯出與分享（P0）

- R7.1 錄音可以匯出成 m4a（AAC）或 wav。
- R7.2 逐字稿可以匯出成 txt、srt、vtt、Markdown；docx 是 P1。匯出時可以選擇要不要包含時間點和說話者。
- R7.3 會議紀錄可以匯出成 Markdown、PDF；docx 是 P1。也可以複製成純文字、Markdown 或富文字，直接貼到 Notion、Slack、Word。介面上的名稱是「保留格式」（英文 Formatted），不用「富文字」：一般人看不懂（2026-10-22 使用者要求，Mac、Windows 一起改）。
- R7.4 整場會議可以打包成 .shiyin 檔，內容包含錄音、逐字稿、說話者名字、會議紀錄、筆記和重點標記，用來備份或傳給同事。
- R7.5 匯出的檔案可以用 macOS 的分享選單（Mail、AirDrop、訊息）分享出去。

### R8 播放與逐字稿（P0）

- R8.1 沿用第二版的功能：同步播放、播放中的段落高亮、底部時間軸、點時間點跳播、搜尋、單段編輯、用詞修正（會一起改到會議紀錄，也可以加進詞彙表）。
- R8.2 可以倍速播放：0.75×、1×、1.25×、1.5×、2×。
- R8.3 逐字稿要顯示說話者，也可以篩選成只看某一位說話者的內容。
- R8.4 時間軸上要標出重點標記和待確認題目的位置。

### R9 管理（P0）

- R9.1 全文搜尋：輸入一個關鍵字，同時搜尋所有會議的標題、逐字稿、會議紀錄和筆記，點搜尋結果可以直接跳到那個位置。
- R9.2 資料夾：每場會議可以放進一個資料夾（例如專案名稱、客戶名稱）。側欄可以切換只看某個資料夾；資料夾可以改名、刪除（刪除資料夾不會刪掉會議）。在某個資料夾裡錄音或匯入，新會議就放進那個資料夾。.shiyin 封包會帶著資料夾名稱。
- R9.3 刪除的會議先放進垃圾桶，30 天後才永久刪除；在這之前都可以還原。
- R9.4 儲存空間：轉錄完成後，錄音自動轉成 m4a 以節省空間（可以在設定裡關掉）；設定裡要看得到總共用了多少空間。

### R10 安裝、首次使用、更新（P0）

- R10.1 以 DMG 發布：打開後把 app 拖進「應用程式」資料夾。附上一頁安裝說明，教使用者怎麼放行第一次開啟。
- R10.2 第一次開啟時要有引導：介紹 app、請求權限、設定整理工具；轉錄模型從引導打開就在背景下載（4.1 起三步，見 R44.6）。
- R10.3 下載模型時要顯示進度，可以暫停和繼續；斷線後可以接著下載；下載完成後要驗證檔案正確。
- R10.4 使用說明沿用第二版的 R14，內容依第三版的功能更新。
- R10.5 從第二版升級時，原本的會議、逐字稿、會議紀錄、詞彙表都要保留。第二版的 Python 環境和舊模型已經用不到，要提示使用者可以刪除，大約可以釋放 4.2 GB。
- R10.6 更新：app 會定期檢查新版本（設定裡也可以手動檢查），有新版時詢問使用者（視窗只列更新內容的前幾項，其餘寫「還有 N 項」，完整說明在官網；4.1 起），同意後自動下載、驗證、替換並重新開啟。下載的檔案要驗證完整性，而且新版 app 的簽章要跟目前的 app 相符，否則拒絕安裝。錄音或轉錄進行中不能更新。更新後資料不能遺失，資料庫要自動遷移。更新檔放在哪裡由發布的人決定（見 R13.2），app 裡可以設定更新網址。
- R10.7 app 更新後，麥克風和系統聲音權限不需要重新允許。

### R11 系統整合（P0）

- R11.1 選單列：錄音控制（開始、暫停、停止、經過時間）、目前工作的進度、打開主視窗、使用說明、結束。
- R11.2 通知：轉錄完成、會議紀錄整理好（附待確認題數）、失敗時都要通知；點通知會打開那場會議。
- R11.3 全域快捷鍵：在其他 app 裡按 ⌃⌥⌘R 也能開始或停止錄音；可以在設定裡關掉。

## 6. 非功能需求

- N1 隱私：見第 4 節。
- N2 效能：以 M1 作為下限估算，以 M3 Pro 的實測為準。
  - 即時逐字稿：暫定文字在 1 秒內出現
  - 正式轉錄：至少 5 倍速
  - 整理一小時的會議：扣掉 CLI 或 API 的回應時間，app 本身的處理不超過 10 秒
  - 任何工作在進行時，介面都不能卡住
- N3 穩定：錄音不能遺失（R1.5）；任何失敗的工作都要能重試；資料庫遷移失敗時不能損毀原本的資料，所以遷移前要先備份。
- N4 系統需求：
  - Apple Silicon（M1 以上）、macOS 26 以上
  - 記憶體：8 GB 以上。app 內轉錄加說話者辨識的峰值約 2.9 GB，會議長短影響不大（3.5 起長錄音分段轉錄，4 小時的會議 2.9 GB，實測）
  - 磁碟：模型約 1.7 GB（轉錄 1.66 GB＋說話者辨識 21 MB），加上錄音（m4a 實測約每小時 10～30 MB）
- N5 介面：繁體中文、英文（跟著 macOS 的語言，R12.1）；使用 macOS 原生元件；支援深色、淺色模式；常用操作都有鍵盤快捷鍵；VoiceOver 能讀出主要元件。
- N6 安全：不開任何網路連接埠；呼叫外部程式一律用參數陣列；API key 存在鑰匙圈。
- N7 可維護性：沿用 SDD 流程；DEBUG 版保留 shiyinctl 控制通道，用來做驗證。

## 7. 待確認問題

## 9. 第 3.1 版：英文版（2026-10-16，使用者已確認）

### R12 多語言（P0）

- R12.1 介面語言跟著 macOS 的語言設定：繁體中文（含台灣、香港）顯示中文，其他語言顯示英文。使用者也可以在「系統設定 → 一般 → 語言與地區」單獨指定拾音的語言。
- R12.2 所有介面文字都要有英文：選單、按鈕、提示、錯誤訊息、通知、狀態、使用說明、首次使用引導、設定、匯出對話框。日期、星期、會議長度依介面語言的格式顯示。
- R12.3 系統權限詢問的說明文字、app 的顯示名稱（英文是 Shiyin）也要有英文。
- R12.4 每場會議有「會議語言」：中文或英文。新的錄音和匯入預設用「設定 → 錄音」的預設會議語言（預設值依介面語言），開始錄音和匯入時都可以改；會議頁也可以改，改了之後可以重新轉錄、重新整理。
- R12.5 會議語言決定三件事：即時逐字稿的辨識語言、正式轉錄的語言和提示詞（Breeze 和 macOS 內建都是）、會議紀錄的輸出語言。中文會議的行為跟 3.0 完全一樣。
- R12.6 內建範本的名稱和說明依介面語言顯示；英文會議的紀錄用英文段落（自訂段落的標題也翻成英文）。使用者自訂的範本照原樣。
- R12.7 匯出的會議紀錄和逐字稿，標題與欄位名稱（摘要、決議、說話者…）用那場會議的語言。
- R12.8 README、DMG 裡的安裝說明都有英文版。

### 不做

- 其他介面語言（日文、簡體中文等）
- 一場會議裡中英文各半的特別處理（中文會議本來就能處理中英夾雜）
- 把會議紀錄翻譯成另一種語言

## 10. 第 3.1.1 版：開源準備（2026-10-16，使用者已確認）

## 11. 第 3.2 版：轉錄準確度（2026-10-16，使用者已確認）

### R14 轉錄準確度（P0）

- R14.1 評估工具（開發用）：給一段錄音和標準答案，算出字錯誤率（中文 CER、英文 WER）、關鍵詞辨識對幾個、說話者標對的比例；同一段錄音可以用不同設定重跑比較。每項改進都要用它比較改前改後。
- R14.2 線上會議（麥克風＋電腦聲音）的兩個聲道分開轉錄，再依時間合併成一份逐字稿。用喇叭開會時麥克風會收到對方的聲音，這些回音不能變成重複的段落。說話者辨識也分聲道做。（評估只在戴耳機時有幫助、說話者標對的比例下降，先不開放，等使用者的真實線上會議再決定，design §17.3）
- R14.4 逐字稿校正（可以在設定裡關掉；2026-10-16 評估後預設開啟）：轉錄完，整理工具依詞彙表、參加者和上下文，找出疑似聽錯的字，列成建議；使用者可以逐條或全部接受，接受後也能還原。不會自動改掉原文。
- R14.5 詞彙表建議：從參加者名單、說話者名字、會議標題、用詞修正過的字，建議加進詞彙表；使用者確認才加入。
- R14.6 採用的改進都有設定可以關掉。關掉時，轉錄的結果跟 3.1 一樣。

### 不做

- 自己訓練或微調辨識模型
- R14.3 轉錄前先偵測有人說話的片段、安靜的部分不送去辨識：2026-10-16 評估漏字大增，不採用（design §17.2、D18）
- 兩個辨識引擎的結果合併
- 即時逐字稿的準確度（系統的即時辨識不吃詞彙表，沒有可以調的地方）
- 一個段落裡換人說話時切開段落（之後再考慮）

## 14. 第 3.4.1 版：穩定性修正（2026-10-19，使用者已確認）

### R18 穩定性（P0）

- R18.1 整理工具的外部程式（claude、codex）還沒讀完輸入就結束時，拾音不能閃退，要照常顯示整理失敗的原因。
- R18.2 錄音中音訊裝置變了（接上或拔掉耳機、藍牙耳機切換、USB 麥克風拔掉、預設輸出換了），要自動接上目前可以用的裝置繼續錄。某個音源超過 3 秒沒有送出聲音資料時，錄音畫面要提示並試著重新連接；接回來後提示消失。
- R18.3 錄音中寫檔失敗（例如磁碟滿了）要馬上停止錄音並說明原因，已經錄到的部分保留、照常轉錄。開始錄音時剩餘空間不到 1 GB 要提醒；錄音中剩不到 300 MB 也要提醒。
- R18.4 筆記（4.1 起在逐字稿分頁頂部，R44.3）自動存檔後，切換分頁、停止錄音再回到筆記，看到的要是最新的內容；接著編輯不能蓋掉之前打的字。
- R18.5 同一個工作在執行時拾音意外結束 2 次，就不再自動重跑：標成失敗並說明，使用者可以按重試。正常結束拾音（結束時中斷了工作）不算。
- R18.6 復原上次沒正常結束的錄音時，任何一步失敗都不能刪掉錄音檔，要留在原處，下次開啟再試。錄音中途當掉、連錄音檔都沒有的空會議要清掉（3.0 起的清理實際上沒有作用）。
- R18.7 只是要知道有沒有存 API key 時（環境檢查、設定頁、首次使用引導），只看鑰匙圈有沒有這個項目，不讀出 key；只有真的要送出請求時才讀。
- R18.8 log 不能寫進整理工具回傳的錯誤內容（可能含逐字稿或會議紀錄），只記錯誤的種類。
- R18.9 匯出對話框匯出的一定是打開對話框時的那一場會議；那場會議在對話框開著時被刪掉，要顯示錯誤，不能顯示「已匯出」。
- R18.10 匯入 .shiyin 封包時，錄音檔只能是封包裡的一般檔案，路徑或符號連結不對就拒絕匯入；transcript.json 讀不出來時要報錯，不能當成沒有逐字稿。
- R18.11 搜尋索引的新增、修改、刪除不能掃描整張索引：存一場會議的逐字稿要花的時間，不能隨資料庫裡的資料變多而變長。復原會議紀錄的上一版時，標題的搜尋索引也要更新。
- R18.12 轉錄中結束拾音（在確認對話框按「結束」）時，要等轉錄停下來再結束，不能在結束時當掉（系統顯示「拾音意外結束」）。最多等 10 秒。（2026-10-19 驗證 R18.5 時發現，原本就有的問題）

### 不做（這一版）

- 說話者辨識可以取消；即時逐字稿中途失敗的提示
- 無障礙、鍵盤操作；AppModel、SettingsView 拆檔
- 錄音中暫停轉錄工作

## 15. 第 3.5 版：錄完就有紀錄、認得說話者、可以提問（2026-10-19，使用者已確認功能清單）

### R19 新功能（P0）

- R19.1 草稿紀錄：停止錄音後，用錄音中的即時逐字稿馬上整理一份草稿，不等正式轉錄。畫面標明是草稿；正式轉錄和整理完成後自動換成正式版。草稿的時間點也能點，跳回錄音。使用者改過草稿時，換成正式版不能把改的內容弄丟（留在版本紀錄，並提示）。沒有即時逐字稿（關掉了、中途失敗、匯入的檔案）或錄音太短時，照原本的流程。
- R19.2 AI 猜說話者：正式整理完後，整理工具從對話內容（互相稱呼、自我介紹、參加者名單、認識的人）猜出還沒有名字的說話者是誰，附上根據（哪一段、什麼時間），列成建議。使用者按「套用」才改名，也可以忽略。不能拖慢會議紀錄完成的時間。
- R19.3 聲紋：使用者替說話者取名（自己改或套用建議）時，拾音記住這個人的聲紋（只存在本機）。之後的會議分出說話者後，跟記住的聲紋比對，夠像的自動帶入名字並標「自動」；使用者可以改正或取消，改正後也記住。同一個人可以有多份聲紋（不同收音環境）。設定裡可以查看認識的人、改名、刪除某人或全部聲紋、關閉這個功能。聲紋不放進匯出的封包。自動帶入的名字寧可少、不能錯：誤認成別人的比例要很低（標準見 design §21.4.1）。
- R19.4 偵測會議、提醒錄音：線上會議的 app（Zoom、Teams、Webex、FaceTime、Slack、LINE、Discord，以及可能在開 Google Meet 的瀏覽器）開始用麥克風、拾音沒在錄音時，提醒「要開始錄音嗎？」，一鍵開始（用設定的錄音來源）。那個 app 停止用麥克風、拾音還在錄時，提醒「會議好像結束了，要停止錄音嗎？」。只提醒，不自動開始或停止。設定裡可以關閉，也可以對某個 app 選「不要再提醒」。
- R19.5 標記重點的全域快捷鍵：錄音中，在任何 app 按 ⌃⌥⌘B 就標記重點，不用切回拾音，要有聲音或選單列圖示的回饋。設定裡可以關閉（跟錄音的快捷鍵分開）。不在錄音時不佔用這組按鍵。
- R19.6 對會議提問：在一場會議裡用自然語言提問，回答附上錄音時間點，點了跳過去。也可以對所有會議（或目前的資料夾、最近 30 天）提問，回答附上是哪一場會議、哪個時間點，點了打開那場會議並跳過去。問答紀錄保留在會議裡（跨會議的保留在提問視窗）。用設定的整理工具，可以取消；選「不整理」時不能用，並說明原因。
- R19.7 回報問題：「說明」選單有「回報問題…」。先顯示會附上的資訊：版本、macOS、晶片、記憶體、轉錄引擎、說話者辨識開關、整理工具的種類、最近失敗的工作的錯誤種類。使用者確認後，用瀏覽器打開 GitHub 的新 issue 頁面並帶入內容；也可以複製內容自己寄。不帶會議內容、檔名、API key。

### R20 改進

- R20.1（P0）整理不等校正：轉錄完，逐字稿校正和整理同時進行，不排成先後。會議紀錄的內容跟現在相同（整理本來就不吃還沒接受的校正）。
- R20.2（P0）一次處理同一個詞的校正：同樣的「原文 → 建議」可以一次全部接受或忽略，顯示有幾處。原本一條一條處理的方式保留。
- R20.3（P1）長會議的介面：播放、錄音時，不能每次更新畫面都重算整份逐字稿；改說話者名字、標記重點、改一段文字這類操作，不能整份重新讀取所有會議。2 小時、2,000 段以上的會議，播放時跟隨、捲動要流暢：播放時逐字稿列表只在換段時重算，上面這些操作主執行緒每次不超過 50 ms（做法見 design §21.12）。
- R20.4（P1）大檔案匯入匯出在背景：匯入（錄音、影片、封包）、匯出（含封包、錄音）不卡住畫面，顯示進行中；完成或失敗有提示。
- R20.5（P1）用 API 整理可以取消；網路暫時出錯（連線中斷、逾時、伺服器 5xx、429 太多請求）自動重試一次。key 錯誤、格式錯誤這類不重試。
- R20.6（P1）草稿保留：待確認的回答、逐字稿單段的編輯，切換分頁、換會議、結束拾音都不會不見，下次打開還在，直到送出或取消。
- R20.7（P2）長錄音分段轉錄：4 小時的會議，轉錄時的記憶體峰值明顯降低（目標少 1/3 以上），逐字稿品質不變：分段的地方不漏字、不重複，評估資料的錯字率不能變差。
- R20.8（P2）第一次使用不用等下載：轉錄模型還沒下載好時，新的會議先用 macOS 內建辨識轉錄，模型在背景下載。下載好後，用內建辨識轉錄的會議顯示「可以用 Breeze 重新轉錄（比較準）」。

### 不做（這一版）

- 行事曆整合、待辦加進「提醒事項」（之後再排）
- 偵測到會議就自動開始錄音（只提醒：沒經過同意就錄音有禮儀和法律的問題）
- 錄音中即時顯示是誰在講（聲紋只在正式轉錄後比對）
- 聲紋在不同電腦之間同步、匯出匯入認識的人
- 對會議提問用本機的語意搜尋（embedding 模型）；跨會議用全文搜尋找相關片段
- 回報問題由 app 直接上傳（只打開瀏覽器）
- 邊錄邊正式轉錄（草稿紀錄先解決等待時間）

## 16. 3.5 之後的修正：鑰匙圈的存取確認、工具列（2026-10-20，使用者同意先做）

### R21 修正（P0）

- R21.1 打開設定頁、切換整理工具時不讀出 API key（只看有沒有存，R18.7）。模型清單要使用者按「選擇」才去取；剛存好 key 時可以先取。
- R21.2 讀 API key 時 macOS 沒有允許（使用者按「拒絕」、關掉確認視窗），錯誤訊息要說明是 macOS 沒讓拾音讀取，告訴使用者下次要輸入這台 Mac 的登入密碼並按「永遠允許」，或重新貼上 key；不能說「還沒有填」。OpenAI 相容 API 讀不到 key 時不能不帶 key 就送出。
- R21.3 拾音開著時，同一個 key 只向鑰匙圈讀一次，之後用記在記憶體的：使用者只按「允許」（不是「永遠允許」）時，整理、逐字稿校正、猜說話者、提問不會各問一次。存新的 key、刪除 key 時一起更新。
- R21.4 儲存 key 失敗時（例如鑰匙圈裡有舊版拾音存的 key、macOS 不讓取代）要說明原因和怎麼處理，不能看起來像存好了。設定頁和首次使用引導都一樣。
- R21.5 視窗在最小寬度（960）到預設寬度之間，沒在錄音和錄音中，工具列的按鈕都不能被收進「>>」。「匯入」移到側邊欄下方（垃圾桶那一列的右邊），⌘O、「檔案」選單、拖進視窗照舊。

### 不做（這一版）

- 把 API key 改存到鑰匙圈以外的地方（N6：key 只能存在鑰匙圈）

## 17. 重新辨識說話者（2026-10-20，使用者已確認）

### R22 重新辨識說話者（P0）

- R22.1 會議頁「更多 → 重新處理」有「重新辨識說話者…」：可以選「大約幾個人」（自動判斷、2～12 人），按「開始」只重新分辨誰在說話，不重新轉錄。逐字稿的文字、校正、編輯、重點、會議紀錄都不變。52 分鐘的錄音要在 2 分鐘內完成。

- 改預設的分群門檻（一般會議會被拆成太多人）
- 重新辨識後自動重新整理會議紀錄（會議紀錄可能被使用者改過，讓使用者決定）

## 18. 第 3.6 版：說話者分錯了很好改（2026-10-20，使用者已確認規劃）

### R23 說話者的修正（P0）

- R23.1 合併說話者：說話者的改名小視窗有「合併到…」，選另一位說話者，這位的段落全部併過去。會議紀錄裡的名字跟著換（留一個版本），兩人的聲紋合成一份。可以在說話者的改名小視窗或逐字稿的右鍵選單復原（R44.4）。
- R23.2 改這句的說話者：逐字稿按右鍵有「這句是誰說的」「這段連續的話是誰說的」（同一位說話者連續的幾句），選一位說話者或「新的說話者」。改過的句子之後「重新辨識說話者」時保留（跟著原本那位說話者對應到的新說話者）。可以復原。沒有段落的說話者自動拿掉。
- R23.3 分不準時提醒：說話者辨識完自我檢查，可能把人併在一起時（門檻用評估資料定），逐字稿分頁上方提示「說話者可能分得不夠…」，附「重新辨識說話者…」和「不用了」。使用者已經選過人數的會議不提示。一般會議（AMI、AISHELL-4、使用者的真實會議）不能誤報。

### 不做（這一版）

- 改過句子的說話者後重新算聲紋（要再跑一次聲紋模型，之後再說）
- 跨會議合併說話者、多層復原（只復原最近一次）

## 19. 第 3.7 版：錄音前就減少錯誤（2026-10-20，使用者已確認規劃）

### R24 錄音和匯入（P1）

## 24. 待確認可以按是或否、聲紋沒把握時先問（2026-10-22，使用者已確認）

第 23 節是 iPhone 版（在 `ios` 分支上）；這一節三個平台一起做。

### R32 待確認的是非題（P1）

- R32.1 整理時，整理工具要標出能用「是」或「不是」回答的題目，題目寫成是非題（例如「負責人是小田切嗎？」）。要使用者說出答案的題目（例如「這個系統的正確名稱是什麼？」）不算。
- R32.2 是非題顯示「是」「不是」兩個按鈕，按了就算回答。按「不是」時出現輸入框，可以填正確的答案，也可以不填。其他題目跟以前一樣用輸入框；「略過」照舊。
- R32.3 送出後跟以前一樣由整理工具依回答修正（R6.5）。回答的文字依會議語言：「是」「不是」（英文 Yes、No，日文 はい、いいえ），不是而且有填答案時接在後面。
- R32.4 Mac、Windows、iPhone 一致：同一份結構化輸出、提示詞和畫面規則，標準答案（R28、R31）要跟著重新產生。以前整理的會議紀錄沒有這個標記，一律當成要打字的題目；重新整理後才有按鈕。

### R33 聲紋沒把握時先問，認錯了一步改對（P1）

- R33.1 聲紋很像、而且跟第二像的人差得夠遠，才直接帶入名字（標「自動」，同 R19.3）。夠像但沒那麼有把握的，不帶入，改成待確認的是非題：「『說話者 3』是 weiwei 嗎？」，附上原因（聲音跟之前的 weiwei 很像）。門檻在 design §21.4。
- R33.2 待確認裡的說話者題目（聲紋沒把握的、AI 從對話內容猜到的，R19.2）：按「是」就帶入名字並記住聲音；按「不是」可以從最像的幾位認識的人裡選，或打名字，也可以不填（就不帶入）；「略過」照舊。送出時跟其他題目一起處理，這一部分不經過整理工具。
- R33.3 會議清單和紀錄頂部（R44.2）的待確認題數包含說話者題目。
- R33.4 點「自動」帶入的名字：除了「不是他」，直接列出最像的幾位認識的人和「其他人…」，選了就一次改名、記住聲音、改掉會議紀錄裡的名字。

### 不做（這一版）

- 選擇題（列出幾個選項讓使用者選）
- 記住「不是他」（存反例，下次不再帶成同一個人）、聲紋的每一份樣本看得到也刪得掉：先看 R33 之後誤認還多不多
- app 自己從題目的文字判斷是不是是非題（D90）

## 25. 很短的一句被算到旁邊的人（2026-10-22，使用者回饋）

### R34 短句的說話者（P1）

- R34.1 輪流講話時，很短的一句（約 2 秒以內）要盡量標成真正說話的人，不能因為太短就併進旁邊那個人。用有標準答案的評估資料量（AMI、AISHELL-4，只算沒跟別人同時講話的句子）：2 秒以內的句子標對的比例要明顯提高，整體（含長句）不能變差，分出的人數不變，處理時間不明顯變長（design §6.3.2）。
- R34.2 同時有兩個人講話（一個人講、另一個人插一句「嗯」）時，拾音一次只標一個人，這一版不處理。
- R34.3 Mac、iPhone 用同一份說話者辨識（FluidAudio），一起改；Windows 的說話者辨識不同（D58），用 Windows 的評估資料另外量、另外改（design-windows §9）。
- R34.4 只影響之後轉錄、重新轉錄、重新辨識說話者的會議；以前的會議不動，要的話用「重新辨識說話者」（R22）。

## 30. 匿名使用統計（2026-10-22，使用者已確認）

### R40 匿名使用統計（P1）

- R40.1 收什麼（每天一份匯總）：
  - 活躍度：匿名安裝 ID（第一次啟動時隨機產生，跟硬體、帳號無關，可以重設）
  - 環境：平台（mac、windows）、app 版本、系統版本、晶片或 CPU（例如 Apple M3 Pro）、介面語言
  - 用量：錄音、匯入各幾場和總秒數；轉錄的語音秒數和實際花的秒數、用哪個引擎（Breeze、系統內建或快速辨識、日文 Whisper）、各會議語言的場數；說話者辨識（含重新辨識）幾次；用哪種整理工具整理了幾次；提問幾次
  - 失敗：錄音、轉錄、說話者辨識、整理各失敗幾次（只有次數）
- R40.2 絕不收：會議標題、逐字稿、會議紀錄、筆記、重點、詞彙表、人名、聲紋、檔名和路徑、API key、整理工具的網址、錯誤訊息的全文。
- R40.3 怎麼送：
  - 一天最多送一次，送已經過完的日子（不送當天還在累計的）；沒有用量的日子也送一份（只有活躍度和環境），才算得出活躍天數
  - 送不出去（沒網路、伺服器錯誤）就留著下次再送，超過 3 天的丟掉，不一直重試
  - 只送到建置時寫進 app 的網址（https）；沒有網址就完全不送、也不累計
  - DEBUG 版不送（只在用 shiyinctl 把網址設在記憶體時送，給驗證用）
- R40.4 告知與控制：
  - 設定 → 進階的最下面只有一行「匿名使用統計」和「詳細…」按鈕（2026-10-22 使用者決定不要太顯眼；問過能不能不給關，決定保留開關，理由見 design D100）。按下去的小視窗裡：
  - 開關「分享匿名使用統計」預設開；說明收什麼、不收什麼
  - 不顯示送出的 JSON（2026-10-22 使用者決定；收什麼寫在說明、README，程式也是開源的）
  - 「重設匿名 ID」：之後送的資料跟之前的連不起來
  - 關掉之後立刻停止送、清掉還沒送的資料
  - 使用說明的「資料與隱私」、README（中英）、官網的隱私說明照實寫出來（版本說明不寫：2026-10-22 使用者決定）
- R40.5 不影響其他功能：送統計在背景進行，失敗不顯示錯誤、不影響錄音和轉錄；統計的檔案壞掉就重新開始，不讓 app 出錯。
- R40.6 後台（2026-10-22 使用者決定用 Cloudflare，不另外架主機）：Cloudflare Workers＋D1，程式放在 repo 的 `workers/usage/`，網址 `https://usage.weibuilds.com/v1/usage`。檢查格式、同一台同一天覆蓋不重複算、不存 IP；送出的格式、回應見 design §30.4、§30.10。
- R40.7 Windows 版做一樣的功能（R28 跟 Mac 一致），送一樣的格式（`platform` 是 windows），報表可以分平台看。2026-10-22 使用者決定跟 4.0.0 一起發（原本排在之後）：Mac、Windows 的 4.0.0 都帶統計。

## 32. 更準的中文、英文轉錄：換成 Qwen3-ASR（2026-10-24，使用者要求打磨辨識準確度）

2026-10-24 使用者要求「有效提升辨識準確度，從第一性原理思考」。先量現況：Breeze ASR 25 的錯誤主要是多人同時說話的漏字（AISHELL-4 漏掉的字裡 35% 是重疊處）和同音字替換，解碼參數（no_context、不降溫重試、beam 8…）換來換去差不到 1%，瓶頸在模型。2026 年初開源的 Qwen3-ASR（Apache-2.0，llama.cpp 2026-04 起支援）在同一套評估資料上：AISHELL-4 16.2%（Breeze 25.7%）、AMI 英文 31.6%（32.6%）、合成中英夾雜會議 2.0%（5.2%）、TaiMECS 台灣國語 1.8%，Apple Silicon 上 17 倍速（Breeze 9 倍）。台灣微調版 TEA-ASR 1.1 在乾淨錄音更好（原生繁體），但多人吵雜錄音會跳針、整段漏（AISHELL 34.8%），日文也壞掉，不採用。Qwen3-ASR 原版輸出簡體，app 自己轉成台灣繁體後，繁簡也算錯的錯誤率仍比 TEA 低（TaiMECS 2.0% vs 2.8%）。

### R43 Qwen3-ASR 轉錄引擎（P0）

- R43.1 新的正式轉錄引擎 Qwen3-ASR 1.7B（llama.cpp，阿里巴巴開源，Apache-2.0），設定裡可以選；**預設維持 Breeze ASR 25**（聯發科）——2026-10-24 使用者決定：台灣的公司會顧慮中國的模型，數字再好也只當選項，介面寫清楚來源和「全程本機、不連網」。日文會議照舊用 Whisper large-v3-turbo（評估：Qwen3-ASR 日文 17.1%、turbo 9.0%）。
- R43.2 中文逐字稿一律繁體、台灣用字：模型輸出簡體，app 依 OpenCC 的字表（Apache-2.0）轉成繁體，詞組優先、單字其次，「臺」寫成「台」；英文、數字、標點不動。評估時繁簡寫錯也算錯，台灣語料的錯誤率要 ≤ 2.5%。
- R43.3 詞彙表當作提示（Qwen3-ASR 的 contextual biasing）：有詞彙表時關鍵詞辨識對的比例不低於 Breeze（合成會議 5/6）。
- R43.4 門檻（評估工具 R14.1，改前改後都要量）：AISHELL-4 ≤ 20%、AMI 不比 Breeze 差、合成中英夾雜會議 ≤ 3%、TaiMECS ≤ 2.5%；Apple Silicon 的速度不低於 Breeze（≥ 10 倍速）。
- R43.5 多人同時說話、吵雜時不能跳針（同一個字重複到截斷）、整段亂掉或編出沒說過的話：偵測重複和截斷，先加重複懲罰重試，再不行就把那一段切短；殘餘的重複不寫進逐字稿；輸出比那段有聲音的時間能講的還多時再解一次，兩次不一致就不留；這些段落標成低信心。
- R43.6 段落有時間點和說話者：引擎本身不給時間點，app 自己分段（在換人說話處的安靜點切，每段最長 15 秒），每段的時間就是段落的時間；說話者辨識、聲紋、短句再確認（R34）照舊可以用。段落比 whisper 的粗，混到第二個人的段要照說話者片段再切，說話者標對的比例不低於 Breeze（評估：理想的說話者辨識下 AISHELL 98.2%、AMI 97.5%；whisper 的段落 96～97%）。
- R43.7 模型下載：選了 Qwen3-ASR 才下載，模型（約 2.2 GB）和音訊編碼器（約 0.36 GB）兩個檔案一起下載、各自驗證 SHA-256，流程同 R10.3；還沒下載好時，已經有 Breeze 的用 Breeze，沒有的照 D35 先用 macOS 內建。沒選的人完全不受影響。
- R43.8 記憶體 8 GB 的 Mac 也要能跑（模型載入約 2.6 GB）；轉錄完就釋放。
- R43.9 Windows 版用同一個引擎（llama.cpp 官方預建的 Windows 版：CPU x64／ARM64、CUDA、Vulkan（AMD，R4.7）；用它的 llama-server 當子程序，design-windows §8.4、D95）、同一套轉繁體和分段規則，分段用同一份說話者片段比對（design-windows §8.4）。
- R43.10 可以關掉（R14.6）：預設（Breeze）的轉錄流程跟 4.0.0 完全一樣；選過 Qwen 再選回 Breeze 也一樣，Breeze 的模型檔不會被刪掉。

## 33. 減法：三個分頁、五個動作、四頁設定、三步引導（2026-10-24，使用者決定先做減法）

2026-10-24 使用者看過 PM 檢視後決定：先做減法那一版。依據是第一性原理（開會的人要的是錄得到、一份可信的紀錄、帶得走）和使用者自己 11 場的用法：改說話者名字 8 次、校正建議接受 414 條，但「筆記」分頁 0 次、資料夾 0 個、書籤 1 次、範本 10 場都是「一般」。有用的是紀錄本身和它的正確性，周邊功能幾乎沒人碰，介面卻為它們長厚了：會議頁六個分頁、「更多」十一項、設定七個分頁、引導五步。

### 不做（這一版）

- 側欄「待確認 N 題」的黃字改成只標最近的（Q-2）、紀錄就地編輯（U-7）、寄給與會者和待辦進提醒事項（P-2，下一版「帶走」）
- 減少設定項目本身（只搬位置、加分組；每個開關都還在）
- 整理工具的費用寫成精確的數字：只寫「用你的訂閱，不另外收費」「依用量計費，一小時的會議通常不到台幣 10 元（2026-10 估）」

## 34. 整理工具設定好才用、失敗說清楚怎麼修（2026-10-25，匿名統計發現，使用者決定三項都做）

4.0.0 的匿名統計（10/22～10/24，48 台）：整理失敗比成功多（扣掉一台一天匯入 103 場的，失敗 49、成功 42），12 台有失敗，其中 6 台一次都沒成功過，都是第一天、第一場會議就失敗，好幾台之後就沒再用。程式碼看下來：引導和設定都能選沒安裝的 claude、codex，選 API 不填 key 也能按下一步；4.1 的引導在「你平常用哪個 AI？」點一下就把沒填 key 的 API 寫進設定；自動用 claude 時只看有沒有裝、不看有沒有登入（使用者自己唯一的一次失敗就是「Not logged in」）。這類設定問題一兩秒就失敗，畫面上一直有「重試」，一場會議被按到 17 次失敗。統計只有失敗次數，看不出原因。

2026-10-26 使用者決定：R45～R47 是小修正，Mac、Windows 一起發布成 4.1.1。

### R45 整理工具設定好才用（P0）

- R45.1 「準備好」：不送請求、不花額度、不跳出鑰匙圈的確認就能判斷。
  - Claude Code、Codex：這台電腦找得到 CLI，而且登入狀態不是「沒有登入」（看不出狀態時當作準備好）
  - Anthropic、OpenAI、Gemini API：鑰匙圈裡有存 key（只看有沒有，不讀出來）
  - OpenAI 相容 API：填了合法的網址和模型（key 可以不填）
- R45.2 引導的整理工具這一步，選了不等於設定好，準備好才寫進設定：
  - 第一段「你平常用哪個 AI？」只是篩選第二段的選項，點了不改設定
  - 選了 API：貼上 key 按「儲存」才寫進設定；沒存 key 就離開這一步，整理工具維持原狀（沒選過就是「還沒設定」，R35），選項下面寫清楚
  - 選了 Claude Code、Codex（只有裝了才會列出）：立刻查登入狀態；沒登入顯示「還沒登入」和「登入」按鈕，登入完回來按「重新檢查」，顯示已登入才寫進設定
  - 寫進設定時自動測試一次（同設定頁的「測試整理工具」，送一個很短的請求），顯示「可以使用」或失敗的原因；失敗是設定問題（R46.1）就不寫進設定，其他失敗（連不到、伺服器忙、逾時）保留並提醒
  - 「下一步」「略過」照常能按，不卡住引導；選「先不用」照舊寫成「不整理」
- R45.3 設定頁的整理工具：
  - 選單裡沒安裝的 claude、codex 寫「沒有安裝」、不能選；已經選了的照樣顯示
  - 選的整理工具還沒準備好時，選單下面寫原因和怎麼修（貼上 API key、登入、填網址和模型），並寫「設定好之前不會自動整理」
  - 存好 key、重新檢查顯示已登入之後，自動測試一次
- R45.4 還沒準備好時不排工作：自動整理、逐字稿校正、猜說話者、草稿紀錄都跟「還沒設定」一樣不排，不會出現「整理失敗」。會議頁放紀錄的地方寫「整理工具還沒設定好：原因」和按鈕（「打開設定」，沒登入時「登入 Claude Code／Codex」）；手動的整理、依回答修正、提問被擋下時也這樣說。準備好之後的會議照常自動整理，之前沒整理的按「整理成會議紀錄」。
- R45.5 Mac、Windows 一起做（R28）；iPhone 之後接（`ios` 分支，沒有 CLI，只有 API 的規則）。

### R46 整理失敗時說清楚怎麼修（P0）

- R46.1 失敗分兩種：
  - 設定問題：沒安裝、沒登入或登入過期、沒填 key、key 錯誤或沒有權限（HTTP 401、403、key 不對的 400）、OpenAI 相容 API 沒填網址或模型、設定為不整理
  - 其他：連不到、伺服器錯誤、額度或用量上限、逾時、回傳格式不對、逐字稿太長…
- R46.2 設定問題的失敗：會議頁的失敗橫幅和通知寫原因，按鈕是「打開設定」（沒登入時「登入 Claude Code／Codex」），不放「重試」；整理工具準備好之後（改了設定、登入了、測試成功），橫幅的按鈕變回「重試」。其他失敗照舊有「重試」。
- R46.3 出現設定問題的失敗後，暫停自動整理（同 R45.4 的「還沒準備好」），直到整理工具的設定改了（換工具、存或刪 key、改網址或模型）、重新檢查顯示已登入、測試成功，或重新打開拾音；不讓之後每一場會議都再失敗一次。
- R46.4 Mac、Windows 一起做。

### R47 匿名統計記整理失敗的種類（P1）

- R47.1 整理失敗另外記每一種的次數：沒安裝、沒登入、沒有 key、key 被拒、額度或用量上限、逾時、連不到、回傳格式不對、其他（一次失敗只算一種）；也記失敗時用的整理工具種類（Claude Code、Codex、API、本機）和其中幾次是草稿整理。只有次數，R40.2 不變（不收錯誤訊息）。
- R47.2 原本的「整理失敗次數」照舊（舊報表不變）；後台加欄位，舊後台收到多的鍵會忽略，app 可以先發布。
- R47.3 Mac、Windows 送一樣的格式。

### 不做（這一版）

- 引導裡沒有 key 時推薦哪一家（例如 Gemini 的免費額度）：免費額度的條款跟「錄音不外流」的說法有衝突，要另外決定
- 統計記每一場會議失敗了幾次（只記工作的次數，草稿另外記）
- 自動幫使用者重試（設定問題重試也不會好；其他失敗照舊手動重試）

## 35. 忘了停止錄音（2026-10-27，使用者新需求、已確認做法）

使用者：「如果我今天忘記暫停錄音，他就會繼續一直錄下去」。現在只有線上會議的 app 停用麥克風時會問「會議好像結束了，要停止錄音嗎？」（R19.4），而且只提醒；現場會議沒有任何提醒。忘了停會錄好幾個小時的空白：檔案很大、轉錄跑很久，空白的地方還可能轉出沒說過的話。2026-10-27 使用者選了：先提醒再自動停止、15 分鐘提醒 30 分鐘停止、轉錄跳過最後的空白但錄音檔保留。

2026-10-27 使用者決定：R48 發布成 4.1.2（Mac、Windows）。

### R48 忘了停止錄音（P1）

- R48.1 錄音中一直沒有人說話滿 15 分鐘：通知「好像沒人在說話了，要停止錄音嗎？」，按鈕「停止錄音」「繼續錄」；錄音畫面、選單列也顯示同一句和這兩個按鈕。按「繼續錄」重新計時，之後又滿 15 分鐘沒人說話會再提醒。
- R48.2 提醒之後還是沒人說話，滿 30 分鐘就自動停止錄音：跟按「停止」一樣存檔、轉錄、整理。通知「已自動停止錄音：30 分鐘沒有人說話」，點了打開那場會議。
- R48.3 自動停止的會議只轉錄到最後有人說話之後 15 秒（2026-10-27 驗證時改：原本 1 分鐘，空白處 Breeze 會生出沒說過的話），後面的空白不轉錄；錄音檔完整保留、可以播放。會議頁寫「最後 N 分鐘沒有人說話，沒有轉錄」；要轉錄全部時用「重新處理 → 重新轉錄」。
- R48.4 「有人說話」要寬鬆判斷，寧可晚停不要誤停：線上會議對方在說話（電腦聲音）也算；即時逐字稿有在跑時，看它有沒有新的字（打字、關門這類聲音不算說話）；沒有即時逐字稿時（關掉了、沒辦法啟動）改看聲音大小。暫停錄音時不計時。
- R48.5 設定 → 錄音與轉錄 → 提醒與快捷鍵：開關「很久沒人說話時提醒，30 分鐘後自動停止」，預設開。關掉時兩個都不做。
- R48.6 跟「會議好像結束了」（R19.4）、收音提醒（R24、R42）同時存在、各自提醒。
- R48.7 Windows 一起做（R28）；iPhone 之後接（`ios` 分支）。

### 不做（這一版）

- 錄太久的上限（例如超過 4 小時就算有聲音也提醒）
- 自動停止時直接裁掉錄音檔
- 依會議行事曆的結束時間提醒

## 36. 企業伺服器：在機房轉錄、整理（2026-10-27，使用者新需求、已確認方向）

使用者：「個人電腦算力不足，沒有 NV 導致轉錄超慢，所以想要透過公司機房做轉錄跟分析，AI 分析可以選用公司後端提供的或是自己本地原本提供的」。現況：沒有 NVIDIA 顯示卡的 Windows 電腦只能用 CPU 轉錄（朋友的電腦 40 分鐘的會議 CPU 轉了 30 分鐘，CUDA 約 8 分鐘）；8 GB 的 Mac 跑 Breeze 或 Qwen3-ASR 也很吃記憶體。

2026-10-27 使用者確認（同一天說「server 要可以有後台可以看每個員工的數據，原本 app 在設定多一個企業伺服器設定即可，上傳語音開始進行轉錄」，介面的名稱用「企業伺服器」）：
- 不另外做一個企業版的 app：同一個拾音，連上企業伺服器才有這些功能。沒連的人完全不受影響。
- 伺服器是另外的**私人專案**（之後可能給別的公司用），不在這個 repo。這一節只寫 app 這邊和兩邊的約定（API，design §36）。
- 伺服器第一版只負責「算」：錄音上傳、轉錄完、app 取回結果後就刪掉。會議照舊存在各人的電腦。
- AI 分析：「企業伺服器」是一種整理工具，原本的 Claude、Codex、各家 API 照樣可以選。伺服器後面接機房自架的模型或公司簽約的雲端 API，由公司設定。
- 登入：在 app 輸入伺服器網址，到伺服器的登入頁用公司帳號登入，登入後就能用。哪些帳號可以登入（例如只限公司網域、信箱驗證過的帳號）由伺服器決定。

### R49 連企業伺服器（P0）

- R49.1 設定 → 進階的最上面一組「企業伺服器」：輸入網址、按「登入」。app 先確認那是拾音的伺服器（不是的話說明「這個網址不是拾音的伺服器」），再打開伺服器的登入頁；使用者在那裡用公司帳號登入，登入完回到拾音，顯示「已登入 <信箱>」和伺服器的名稱（例如公司名稱）、「登出」。拾音不經手公司帳號的密碼。
- R49.2 網址只接受 https（DEBUG 版可以用本機的 http）。連不上、憑證不受信任、不是拾音的伺服器、伺服器的版本太舊或太新，各自說明原因。
- R49.3 登入後預設「正式轉錄」和「整理工具」都改用企業伺服器（伺服器有提供整理時）；設定的「企業伺服器」那一組有「用企業伺服器轉錄」「用企業伺服器整理會議紀錄」兩個開關，可以關掉改回本機的引擎和原本的整理工具。
- R49.4 登入一直有效，不用每天登入：app 自己更新登入。帳號被停用、離職、伺服器撤銷這台電腦的登入時，說明「企業伺服器的登入已失效，請重新登入」，用到伺服器的工作先停著等（不算失敗），重新登入後接著做。
- R49.5 登出：伺服器那邊也撤銷這台電腦的登入，鑰匙圈裡的登入資料刪掉。正式轉錄改回本機的引擎（Breeze 下載好了用 Breeze，沒有的話用 macOS 內建；Windows 用快速辨識），整理工具原本是企業伺服器的改成「還沒設定」（R35）。
- R49.6 登入資料只存在鑰匙圈（Windows 是認證管理員），跟 API key 同樣的規則，不寫進檔案、資料庫、log。
- R49.7 加入連結（2026-10-27 使用者要求）：公司給的加入連結（伺服器的 `/join` 網頁上的「用拾音打開」，`shiyin://join?server=<網址>`）會打開拾音，問「加入 <主機名稱> 的企業伺服器？」並寫出伺服器自稱的公司名稱（4.2.1：名稱是伺服器自己填的，標題用主機名稱），按「加入」就打開登入頁（同 R49.1、R49.2 的檢查），登入後照 R49.3。已經登入同一台：說「已經加入了」。登入的是別台：問的時候寫出新的登入成功之後，目前那台才會登出；登入沒完成就維持原本的登入（4.2.1）。不是拾音的伺服器、網址不對：說明原因，什麼都不改。

### R50 用企業伺服器轉錄（P0）

- R50.1 「正式轉錄」多一個選項「企業伺服器」（登入後才出現）。選了它：錄音結束或匯入後，app 把錄音上傳到企業伺服器，在那裡做說話者辨識和轉錄，結果回到 app；之後的聲紋、壓縮、逐字稿校正、整理照舊在 app 做。
- R50.2 用哪個模型（Breeze ASR 25、Qwen3-ASR）由公司在伺服器設定，app 顯示伺服器用的是哪一個；日文會議照舊用 Whisper large-v3-turbo。詞彙表、會議語言、「先填人數」（R24.2）一起送過去，效果跟本機一樣。
- R50.3 轉錄中顯示階段和進度：「上傳中 N%」「排隊中（前面還有 N 場）」「企業伺服器轉錄中 N%」。可以取消（伺服器那邊也停下來、刪掉錄音）、可以重試；上傳到一半斷線，接著傳，不從頭；app 中途被關掉，下次開啟時接著上傳或接著等結果（R4.2）。
- R50.4 同一段錄音，企業伺服器轉出來的逐字稿跟用同一個模型在本機轉的一樣（同一份轉錄規則，design §36.6）。
- R50.5 連不上企業伺服器時不當成失敗：工作顯示「等企業伺服器」，自動再試；旁邊有「改在這台電腦轉錄」，按了就用本機的引擎（模型還沒下載的話先下載）。錄音、即時逐字稿完全不受影響。
- R50.6 聲紋只存在這台電腦（R19.3、R33）：Mac 在本機辨識說話者、算聲紋（跟伺服器轉錄同時做，分人和聲紋跟本機轉錄完全一樣，伺服器只負責逐字稿）；Windows 的說話者也交給伺服器辨識（伺服器用的是 Windows 版同一個模型，沒有 NVIDIA 的電腦不用自己跑），伺服器把每位說話者的聲紋跟結果一起回傳、轉完就刪，聲紋只存在 Windows 的資料庫。伺服器不存聲紋。
- R50.7 正式轉錄選企業伺服器的電腦，不用下載 Breeze、Qwen3-ASR、顯示卡加速元件（NVIDIA、AMD）：首次使用引導、設定不要求下載，Windows 有 NVIDIA 或 AMD 顯示卡時也不自動下載加速元件。按「改在這台電腦轉錄」或換回本機的引擎時才下載。
- R50.8 錄音送到企業伺服器：只送錄音、詞彙表和轉錄需要的設定，不送筆記、會議紀錄、會議名稱、說話者的名字。

### R51 企業伺服器的整理工具（P0）

- R51.1 整理工具的選單在登入了企業伺服器、公司有提供整理時多「公司（<公司名稱>）」（2026-10-27 使用者：「這裡可以直接選公司，由公司後台設定模型等」、「登入應該都在進階，這裡只選模型，公司有提供就會出現在選項裡」）。登入只在「進階 → 企業伺服器」（R49），整理工具頁不放網址和登入。選了「公司」不用填 key、模型：顯示公司在伺服器後台設定的模型；公司提供不只一個模型時，可以從選單換（列出後台設定的名稱）。整理、校稿、草稿紀錄、逐字稿校正、詞彙建議、猜說話者、對會議提問都可以用（同 R17）。
- R51.2 送出的內容跟其他整理工具相同（第 4 節），只是送到企業伺服器，再由它轉給公司設定的模型；提示詞、範本照舊在 app 裡組好。
- R51.3 「準備好了沒」（R45）：已登入、伺服器有提供模型就算準備好。還沒登入或登入失效時說「到設定 → 進階 → 企業伺服器登入」；已登入但伺服器還沒有模型時說「公司的伺服器還沒有提供整理用的模型，請通知管理者」。失敗的分類（R46）：登入失效、帳號被停用是設定問題；連不上、伺服器忙、逾時是其他。
- R51.5 公司在後台加了、停用了模型，不用重新登入：app 啟動、打開整理工具的設定時重新讀伺服器的資訊（有沒有提供整理、公司名稱、轉錄引擎）和模型清單。
- R51.4 隱私說明寫「送到 <伺服器的主機>（公司的伺服器），再由公司設定的模型整理」。
- R51.6 企業伺服器自己擋下的整理（額度用完、預算用完、整理被暫停、不是拾音的請求，伺服器的 SR11）只顯示伺服器給的那句話（已經是介面的語言），不加「公司的伺服器 回傳 HTTP 429（超過用量限制…）」這種技術的前綴；伺服器自己寫的其他訊息（例如「企業伺服器的整理模型設定有問題，請通知管理者」「連不到整理的模型」）也一樣；伺服器原樣轉回的模型錯誤（例如模型回的 400）照舊加前綴，說明是哪裡出錯。（2026-10-28 使用者看過額度用完的訊息後要求）

### R53 公司詞彙表（P0，2026-10-27 使用者要求）

- R53.1 登入企業伺服器後，app 拿公司在伺服器後台維護的詞彙表（產品名、客戶名、同事的名字…），啟動、打開「說話者與詞彙」設定、登入後更新；連不上時用上次拿到的。
- R53.2 公司的詞跟自己的詞一起用：轉錄（在這台電腦或企業伺服器）、校正逐字稿、整理、猜說話者。轉錄的提示詞有長度上限（中文約 150 字、英文 400 字），自己的詞排前面、公司的接在後面；校正、整理用全部。
- R53.3 「說話者與詞彙」設定多一段「公司的詞彙（N 個）」，唯讀，寫「由<公司名稱>維護」；建議加入的新詞不再建議公司已經有的。自己的詞彙表不會被改。
- R53.4 登出就刪掉公司的詞彙表。只存在 `SHIYIN_HOME`，不送到別的地方（整理時跟自己的詞一樣放進提示詞）。

### R52 其他（P0）

- R52.1 隱私說明（設定、引導、使用說明、官網）：連上企業伺服器時，錄音送到公司自己的伺服器轉錄、不經過其他雲端服務，轉錄完就刪掉；整理的內容送到公司的伺服器，由公司選的模型整理（公司機房裡的模型，或公司接的雲端 AI 服務，不寫成「不經過雲端」）；聲紋不上傳；公司的後台只看得到用量，看不到會議內容。沒連的人照原本的寫法。
- R52.2 匿名使用統計（R40）照舊，多記「用企業伺服器轉錄的分鐘數」「整理工具是企業伺服器」，不記伺服器的網址、公司名稱、帳號。
- R52.3 回報問題（R19.7）寫出有沒有連企業伺服器、伺服器的版本，不寫網址和帳號。
- R52.4 Mac 和 Windows 一起做（R28）：同一份 API、同樣的畫面和文字；app 送給伺服器的內容用標準答案比對（design §36.6）。iPhone 之後接（`ios` 分支）。
- R52.5 可以關掉（R14.6）：沒登入企業伺服器的 app 用起來跟 4.1.2 一樣（轉錄、整理、詞彙表、統計的內容、啟動時不連網也不讀鑰匙圈），看得到的差別只有「進階」最上面的登入區塊（R49.1）；登出之後回到沒登入的狀態（轉錄回到預設的 Breeze、整理工具要重新選，R49.5）。
- R52.6 不信任伺服器的回應（2026-10-28 安裝伺服器前的安全審查，4.2.1）：被入侵或設定錯的企業伺服器、別人做的加入連結，不能讓拾音當掉、卡住或寫爆磁碟（說話者編號、時間、上傳位置、詞彙表都有範圍），不跟著轉址（錄音、逐字稿、token 不會被轉送到別台），加入連結的標題寫主機名稱。

2026-10-28 使用者決定：企業伺服器的 app 這邊發布成 4.2.0（Mac、Windows），不推 5.0.0（企業版還沒有公司在用；等機房裝好、公司開始用，或要給別的公司用時再推大版本）；R52.6 發布成 4.2.1。

### 不做（這一版）

- 伺服器存會議、共享給同事、網頁版
- 伺服器的聲紋庫（全公司的人自動認得）
- 邊錄邊上傳（停止錄音後幾分鐘內就有正式逐字稿，下一版）
- 公司從後台把詞彙表、範本、設定推到每台電腦，或限制只能用公司的整理工具（下一版）
- 同時登入兩個以上的企業伺服器

## 37. Teams 會議的聲音錄不到（2026-10-28，GitHub issue #2）

使用者回報（Windows 4.1.0，Windows 11 25H2 x64，MX330 顯示卡）：「只要 Teams 有開啟的話，在錄製 Teams 的會議部份就收不到聲音」，影片、網頁的聲音都錄得到。原因：Windows 版錄電腦聲音用 process loopback（排除拾音自己，R27 R1.2），新版 Teams（ms-teams.exe）的聲音用這個方法收，Windows 給的全是靜音，也不回報錯誤；Microsoft 自己的 ApplicationLoopback 範例、OBS 的「應用程式音訊擷取」錄 Teams 也一樣，收整個輸出裝置的聲音才收得到（design-windows D129）。同一份回報還有 5 次轉錄失敗，回報和 log 只寫了「WhisperException」，看不出是沒有辨識到語音、模型載入失敗（可能是 2 GB 的顯示卡放不下模型）還是別的。

2026-10-28 使用者決定先做 R54；Teams 的喇叭不是預設裝置、顯示卡載入失敗改用 CPU 這兩項先不做，原因見下面「回報的人回覆之後先不做」。

### R54 Windows 的電腦聲音、轉錄失敗的種類（P0）

- R54.1 Windows 錄電腦聲音要錄得到新版 Teams 會議裡別人說話的聲音，跟其他 app 一樣。
- R54.2 錄的是 Windows 預設輸出裝置（「設定 → 系統 → 音效 → 輸出」選的那個）播放的聲音。錄音中換預設輸出裝置、拔掉耳機時，接著錄新的裝置，錄音不中斷（R18.2）。沒有任何輸出裝置時，電腦聲音那一聲道是靜音、錄音照常，之後接上裝置就開始錄。
- R54.3 錄音中在拾音裡播放錄音，聲音會一起錄進電腦聲音（跟 Mac 不同：錄得到 Teams 的方法排除不了拾音自己）。
- R54.4 回報問題和 log 的「最近失敗的工作」寫出轉錄失敗是哪一種（還沒下載模型、模型載入失敗、whisper 的錯誤代碼、沒有辨識到語音、已取消、Qwen3-ASR 出錯）；Windows 系統元件的錯誤寫錯誤代碼。照舊不寫錯誤訊息和會議內容（M§21.9）。
- R54.5 Mac 版不變（R26.5）。

### 回報的人回覆之後先不做（2026-10-29）

回報的人回覆：Windows 預設的輸出裝置和 Teams 的喇叭都是同一台 USB 會議揚聲器（Jabra Speak 710），R54 就錄得到；拾音畫面上只有麥克風在動、電腦聲音完全不動；失敗的那幾場是「錄音裡沒有辨識到任何語音」（只錄到靜音），不是模型載入失敗。下面兩項這位使用者用不到，有人回報再做：

- Teams 的聲音不在 Windows 預設的輸出裝置上時也要錄到：Teams 的喇叭選了別的裝置（例如 Windows 預設是筆電喇叭、Teams 指定耳機），或是藍牙耳機通話時 Windows 把聲音改送到耳機的「免持（Hands-Free）」裝置（通常是預設的通訊裝置，不是預設裝置）
- 顯示卡（例如 2 GB 的 MX330）載入轉錄模型失敗時改用 CPU 重試，訊息不要叫使用者重新下載模型

### 不做（這一版）

- 同時錄好幾個輸出裝置的聲音
- 讓使用者選要錄哪一個輸出裝置

## 38. 只裝了 Codex、Claude 的桌面版（2026-10-29，Threads 的使用者回饋）

使用者（Windows，AMD 顯示卡）：「預設抓不到 Codex 桌面版，我請 AI 幫我修好了」（同一則的 AMD 顯示卡加速見 R27 R4.7）。原因：Windows 版找 codex 只看 PATH 和 npm 的全域安裝；Codex 桌面版（Microsoft Store）附的 codex.exe 在 `C:\Program Files\WindowsApps\OpenAI.Codex_<版本>_…\app\resources\`，桌面版會先複製到 `%LOCALAPPDATA%\OpenAI\Codex\bin\<雜湊>\` 再執行（OpenAI 的文件沒寫，從 openai/codex 的 issue 查到的，design-windows §10），不在 PATH 上。OpenAI 的文件寫明 Windows 桌面版跟 CLI 共用 `%USERPROFILE%\.codex`，在桌面版登入過，CLI 也是登入的。Mac 也一樣：Codex 桌面版現在叫 ChatGPT（`/Applications/ChatGPT.app`，bundle id 照舊是 `com.openai.codex`），裡面附一份 codex（`Contents/Resources/codex-cli/`）。2026-10-29 在使用者的 Mac 上試過：它的 `login status` 跟 Homebrew 裝的 codex 一樣是已登入，拾音用到的 `exec` 參數都有。

Claude 桌面版也會自己下載一份 Claude Code，但那是桌面版內部用的：Mac 放在 `~/Library/Application Support/Claude/claude-code/<版本>/<雜湊>/claude.app`（只有自己讀得到的資料夾），登入由桌面版管。Anthropic 的條款（code.claude.com/docs/en/legal-and-compliance，2026-10-29 查）允許使用者用自己的訂閱登入原版的 Claude Code，但不允許第三方 app 收集、儲存或轉用 Claude 帳號的登入資料。

2026-10-29 使用者決定：Codex 找不到 CLI 時用桌面版附的；Claude 不用桌面版裡的，改成說明怎麼安裝 Claude Code；Mac、Windows 一起做。

### R55 用 Codex 桌面版附的 codex（P1）

- R55.1 找 codex 的順序：先找使用者自己裝的 Codex CLI（跟現在一樣）；找不到時，用 Codex 桌面版附的 codex。兩個都有時用 CLI。
- R55.2 只裝了 Codex 桌面版的電腦，跟有 CLI 的一樣：自動選整理工具時找得到（R35.1）、引導和設定的整理工具可以選 Codex（R35.3、R45.3）、準備好了沒照樣判斷（R45.1：問 codex 自己有沒有登入，拾音不讀、不複製 Codex 的登入資料）。
- R55.3 設定的整理工具、環境檢查看得出用的是哪一份：用桌面版附的時候寫「使用 <app 名稱> 附的 codex」（用 app 自己的名稱：Mac 現在是 ChatGPT，Windows 是 Codex）。這時沒登入的說明和按鈕改成「打開 <app 名稱> 登入」。
- R55.4 桌面版更新後（安裝位置跟著版本變）照樣找得到，不用重新設定；桌面版移除後當成沒有安裝（R35.4）。桌面版附的 codex 執行失敗時，訊息建議另外安裝 Codex CLI。
- R55.5 不改 Codex 桌面版的檔案和設定，只執行它附的 codex。
- R55.6 Mac、Windows 一起做（R28）；iPhone 沒有 CLI，不適用。

### R56 只有 Claude 桌面版時，說明怎麼裝 Claude Code（P1）

- R56.1 拾音照舊只用使用者自己裝的 Claude Code，不用 Claude 桌面版裡的那一份（上面的原因）。
- R56.2 這台電腦有 Claude 桌面版、找不到 Claude Code 時，引導和設定的整理工具（選的是 Claude Code 或還沒設定時；已經在用別的整理工具就不顯示）裡 Claude Code 那一項不是只寫「沒有安裝」，而是說明「你有 Claude 桌面版：另外安裝 Claude Code（命令列版）之後，拾音就能用你的 Claude 訂閱整理」，附可以複製的官方安裝指令（Windows：`irm https://claude.ai/install.ps1 | iex`，Mac：`curl -fsSL https://claude.ai/install.sh | bash`）和官方說明的連結。裝好、登入之後按「重新檢查」就能選。
- R56.3 選了 Claude Code、這台電腦卻找不到時（R35.4），有 Claude 桌面版的話也加上 R56.2 的說明。
- R56.4 Mac、Windows 一起做（R28）。

### 不做（這一版）

- 用 Claude 桌面版裡的 Claude Code（R56.1）
- 讀 Claude 桌面版、Codex 的登入資料
- 在拾音裡直接執行安裝指令，幫使用者裝 Claude Code、Codex CLI
